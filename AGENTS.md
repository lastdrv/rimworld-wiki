# RimWorld Wiki & Modding Agent Guidelines

Данный файл содержит обязательные системные правила и регламенты для работы в репозитории `rimworld-wiki`. Эти правила всегда активны для AI-агента.

---

## 1. Регламент анализа модов (Mod Analysis)

При получении запроса на анализ любого мода (поиск в каталоге мастерской, по ID или имени) агент **обязан**:
1. **Анализировать последнюю актуальную версию (1.6)** и директорию `Common/`, игнорируя устаревшие папки версий (`1.4/`, `1.5/`).
2. **Проводить исследование кода и данных**:
   * Для XML — исследовать Defs и PatchOperations.
   * Для C#-сборок (`Assemblies/*.dll`) — декомпилировать через `ilspycmd -p -o <scratch_dir> <dll_path>` или инспектировать типы через PowerShell Reflection (предварительно загрузив `Assembly-CSharp.dll`).
3. **Создавать статью в `wiki/mods/<mod_name>.md`** строго по 9-секционному шаблону:
   1. **Основные сведения** (`packageId`, `steam_id`, автор, версии).
   2. **Цель мода** (зачем нужен, решаемая задача).
   3. **Зависимости** (DLC, Harmony, HugsLib и др.).
   4. **Взаимодействие с ванильными DLC** (Royalty, Ideology, Biotech, Anomaly, Odyssey).
   5. **Взаимодействие со сторонними библиотеками и C#-код** (Harmony-патчи, C#-архитектура, ключевые классы).
   6. **Добавляемый контент и его характеристики** (предметы, постройки, события, Hediffs, параметры/урон/стоимость. *Исключение: для модов-русификаторов раздел не создается*).
   7. **Поддержка и статус русификации** (наличие в workshop `294100`, тип перевода: XML или пересборка, статус).
   8. **Дополнительная важная информация** (особые механики, риски совместимости, альтернативы).
   9. **Примечания и технические данные** (пространства имен, классы, методы, структуры данных, Defs, пути).
4. **Обновлять каталог**: Добавлять ссылку на новую статью в таблицу `wiki/mods/index.md`.

## 2. Правило фиксации новых знаний (Актуализация статей)

* **Обязательное обновление**: Если в процессе решения задач, ответов на вопросы пользователя, отладки или углубленного исследования исходников вскрываются новые технические детали о моде (форматы сохранения `.pcc`/`.pcp`, работа с GUID/ID, особенности методов, логика миграции, скрытые механики) — **агент обязан сразу же дополнять и актуализировать статью этого мода в `wiki/mods/`**.
* **Цель**: Исключить повторные исследования в будущих сессиях.

---

## 3. Регламент русификации модов

* **Условие создания файлов**: Файлы перевода в каталоге `russian/<steam_id>/` создаются **исключительно по прямому запросу пользователя** и только для модов, присутствующих в `C:\Program Files (x86)\Steam\steamapps\workshop\content\294100`. По умолчанию при анализе файлы не создаются.
* **Оценка метода**: Определять, достаточно ли XML (`Languages/Russian/Keyed/` и `DefInjected/`), или требуется декомпиляция и пересборка DLL.
* **Правила перевода**:
  * Учитывать жанровый и функциональный контекст мода.
  * **Категорически запрещено переводить** общепринятые короткие аббревиатуры (`HP`, `XP`, `UI`, `ID`, `DLC`, `DPS`, `RNG`).

---

## 4. Регламент задачи «Объяснение XML»

При запросе на объяснение XML-структуры мода:
1. Создавать подкаталог `wiki/mods/<название_мода>/` и переносить туда статью мода, обновив ссылку в `wiki/mods/index.md`.
2. Копировать дерево XML-файлов Defs из `<steam_id>/<1.6>/Defs/`.
3. В строке каждого открывающегося тега добавлять inline-комментарий на русском языке (`<!-- назначение параметра/блока -->`).
4. **Запрет на догадки**: Если точное назначение тега неизвестно — комментарий не пишется.

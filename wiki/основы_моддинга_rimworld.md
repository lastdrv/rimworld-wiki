# Основы моддинга RimWorld

Моддинг в RimWorld — это процесс расширения или изменения функционала игры с помощью XML-деклараций, C#-кода и графических/звуковых ассетов. В данной статье рассмотрены ключевые категории модов, архитектура их папок и базовые принципы работы.

---

## 1. Категории моддинга

### 1. XML-моддинг (Декларативный моддинг)
XML-моддинг позволяет создавать новые объекты и изменять существующие без написания компилируемого кода.
- **Определение объектов (`Defs`)**: Создание вещей (`ThingDef`), построек, предметов, рецептов (`RecipeDef`), фракций (`FactionDef`), исследовательских проектов (`ResearchProjectDef`), видов работ (`WorkTypeDef`) и др.
- **Патчинг (`Patches`)**: Изменение существующих ванильных Defs с помощью `PatchOperationAdd`, `PatchOperationReplace`, `PatchOperationRemove` без перезаписи всего файла.

### 2. C#-программирование (Assemblies)
Используется, когда требуется новая логика, не предусмотренная стандартными классами ванильной игры.
- **Создание компонентов (`CompProperties` и `ThingComp`)**: Добавление уникального поведения предметам или зданиям (например, энергогенератор с особыми условиями).
- **Создание подклассов объектов (`Thing`, `Building`, `Pawn`)**: Кастомное поведение объектов на карте.
- **`GameComponent` / `WorldComponent`**: Логика, сохраняемая вместе с глобальной картой или сохранением игры.
- **Интерфейс (UI)**: Отрисовка собственных окон (`Window`), диалогов и панелей взаимодействия.

### 3. Модификация кода через Harmony (Harmony Patches)
Harmony — это библиотека для C#, позволяющая "налету" подменять или внедрять код в методы классов ванильной игры (`Assembly-CSharp.dll`) или других модов.
- `Prefix` — выполняется до оригинального метода (может отменить выполнение оригинала).
- `Postfix` — выполняется после оригинального метода (может перехватить и изменить возвращаемое значение).
- `Transpiler` — модифицирует IL-инструкции метода прямо в памяти.

### 4. Библиотечные моды (Library Mods / Frameworks)
Моды, которые сами по себе не добавляют игрового контента, но предоставляют общий C# API или расширенный XML-функционал для других модов.
- **Примеры**: *Harmony*, *HugsLib*, *XML Extensions*, *Tabula Rasa Core*.
- При создании собственного мода библиотека прописывается в `<modDependencies>` в `About/About.xml`.

## 2. Стандартная анатомия папки мода

Мод для RimWorld имеет следующую структуру файлов и папок в корне своего каталога (в `Mods/my_mod_name/`):

```text
my_mod_name/
├── About/
│   ├── About.xml           # Манифест мода (Название, Автор, Версия, Зависимости)
│   └── Preview.png         # Обложка мода в списке модов (480x300 или 640x360)
├── Defs/                   # XML-определения объектов
│   ├── ThingDefs_Buildings/# Здания
│   ├── ThingDefs_Items/    # Предметы
│   └── SoundDefs/          # Звуки
├── Patches/                # XML-патчи для изменения чужих Defs
│   └── Patch_MyMod.xml
├── Assemblies/             # Скомпилированные C# .dll файлы
│   └── MyModAssembly.dll
├── Textures/               # PNG-текстуры
│   ├── Things/
│   └── UI/
├── Sounds/                 # WAV/OGG аудиофайлы
└── Languages/              # Файлы локализации (Russian, English)
    └── Russian/
        ├── DefInjected/
        └── Keyed/
```

## 3. Манифест мода (`About/About.xml`)

Каждый мод обязательно содержит файл `About/About.xml`. Пример структуры для версии **1.6**:

```xml
<?xml version="1.0" encoding="utf-8"?>
<ModMetaData>
  <name>My Awesome RimWorld Mod</name>
  <author>YourName</author>
  <packageId>YourName.MyAwesomeMod</packageId>
  <supportedVersions>
    <li>1.5</li>
    <li>1.6</li>
  </supportedVersions>
  <description>Подробное описание мода на русском языке.</description>
  <modDependencies>
    <li>
      <packageId>brrainz.harmony</packageId>
      <displayName>Harmony</displayName>
      <steamWorkshopUrl>steam://url/CommunityFileId/2009463077</steamWorkshopUrl>
    </li>
  </modDependencies>
  <loadAfter>
    <li>Ludeon.RimWorld</li>
  </loadAfter>
</ModMetaData>
```

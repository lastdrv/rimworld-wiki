# Структура игры RimWorld и пути к файлам

В данной статье подробно описано файловое устройство игры RimWorld (версия **1.6**), расположение ванильных ресурсов, сборок C#, модов Steam Workshop, а также пользовательских конфигураций и логов.

---

## 1. Системные пути

### Основная директория игры (Steam)
- **Путь**: `C:\Program Files (x86)\Steam\steamapps\common\RimWorld\`
- **Содержимое**:
  - `RimWorldWin64.exe` — Исполняемый файл игры (Unity).
  - `Version.txt` — Файл версии (например, `1.6.4871 rev590`).
  - `RimWorldWin64_Data/Managed/Assembly-CSharp.dll` — Главная сборка с исходной логикой игры на C#.
  - `RimWorldWin64_Data/Managed/UnityEngine.CoreModule.dll` — Базовые классы движка Unity (Vector3, Color, GameObject и др.).
  - `Data/` — Каталог с ванильным контентом и официальными DLC:
    - `Data/Core/` — Базовый контент RimWorld (XML Defs, Textures, Sounds, Languages).
    - `Data/Royalty/` — DLC Royalty (id: `Royalty`).
    - `Data/Ideology/` — DLC Ideology (id: `Ideology`).
    - `Data/Biotech/` — DLC Biotech (id: `Biotech`).
    - `Data/Anomaly/` — DLC Anomaly (id: `Anomaly`).
  - `Mods/` — Локальная папка для модов разработчика. Все разрабатываемые вручную моды помещаются сюда.
  - `Source/` — Ванильный исходный код/примеры, поставляемые с игрой (при наличии).

### Каталог сторонних модов Steam Workshop
- **Путь**: `C:\Program Files (x86)\Steam\steamapps\workshop\content\294100\`
- **Содержимое**:
  - Подпапки с числовыми ID модов из Steam Workshop (например, `294100/816132178`).
  - Каждый мод содержит стандартную структуру: `About/`, `Defs/`, `Assemblies/`, `Textures/`, `Patches/`.

### Пользовательские данные, настройки и логи
- **Путь**: `C:\Users\lastdrv\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\`
- **Содержимое**:
  - `Player.log` — Основной лог работы игры Unity и всех загруженных C#-сборок. Первоочередной файл для отладки ошибок (NRE, MissingMethodException и т.д.).
  - `Config/ModsConfig.xml` — Список активных модов и порядок их загрузки.
  - `Config/KnowledgeDefs/` — Пользовательские настройки интерфейса и обучения.
  - `Saves/` — Файлы сохранений игры (`.rws`).

## 2. Режим доступа и безопасность файлов

> [!CAUTION]
> При выполнении всех операций агент и разработчик обязаны строго соблюдать следующие уровни доступа:

| Каталог | Назначение | Режим доступа |
|---|---|---|
| `common/RimWorld/` | Исполняемые файлы и ванильные Defs | 🔴 **Только чтение (Read-Only)**. Изменения ванили запрещены. |
| `workshop/content/294100/<чужой_id>/` | Существующие чужие моды | 🔴 **Только чтение (Read-Only)**. Изменение чужих модов запрещено. |
| `workshop/content/294100/<наш_мод>/` | Создаваемые собственные моды | 🟢 **Полный доступ (Read / Write)**. Создание новых папок и их редактирование. |
| `AppData/LocalLow/...` | Логи, конфиги (`ModsConfig.xml`), сохранения | 🟡 **Только по согласованию**. Редактирование с разрешения пользователя. |
| `c:\rim-wiki\wiki\` | Документация и база знаний Wiki | 🟢 **Полный доступ (Read / Write)**. |

## 2. Версионирование игры

- **Текущая версия игры**: `1.6` (сборка `1.6.4871 rev590`).
- **Совместимость версий**:
  - RimWorld использует обратную совместимость для многих XML Defs, однако структура некоторых полей может меняться между major-версиями (1.4 -> 1.5 -> 1.6).
  - В файле `About/About.xml` мода указывается список поддерживаемых версий:
    ```xml
    <supportedVersions>
      <li>1.4</li>
      <li>1.5</li>
      <li>1.6</li>
    </supportedVersions>
    ```
  - Папки мода могут разделяться по версиям для сборок C# и XML:
    - `1.5/Assemblies/`
    - `1.6/Assemblies/`
    - `1.6/Defs/`
    - `Common/Defs/` (общие Defs для всех версий).

## 3. Порядок загрузки модов RimWorld

При запуске игры RimWorld последовательно выполняет следующие шаги:
1. Инициализирует Unity Engine и Mono Runtime.
2. Загружает `Assembly-CSharp.dll` и ванильные ресурсы.
3. Читает `ModsConfig.xml` для формирования порядка загрузки модов (`Core` -> `DLC` -> `Библиотеки` -> `Обычные моды`).
4. Для каждого мода загружает файлы сборок `.dll` из `Assemblies/`.
5. Парсит XML Defs из `Defs/`.
6. Применяет XML Patches из `Patches/` с помощью `PatchOperation`.
7. Запускает статические конструкторы классов с атрибутом `[StaticConstructorOnStartup]` (C#).
8. Выполняет патчинг кода через Harmony (если мод использует Harmony).
